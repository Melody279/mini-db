### 4. 冻结的四个技术决策（答辩会被问，先写死理由）

1. **页大小 8KB**（不是常见的 4KB）。我们的记录大（`orders` 216B），8KB 页一页放 ~37 行，目录开销摊薄；代价是单页刷盘粒度变大，脏页多时写放大略高。
2. **记录全定长**。`RID = (page_id, slot_id)` 直接算出偏移，省掉变长解引一层。代价是 `char(64)` 地址字段会浪费空间（如"钟楼"只占 6 字节却占 64）。备选方案：W2 若空间吃紧，加 overflow page 支持变长（记入待讨论）。
3. **TSV 协议 + 独立网关**。C++ 不手搓 HTTP：引擎只管"一行命令/多行结果"，JSON 与登录态交给网关，App 侧调试也简单（curl 就能看到原样）。
4. **锁用超时回滚，不用等待图**。默认 50ms 超时，超时即回滚该事务。理由：实现成本低、死锁不会挂死进程；代价是可能误杀长事务。W3 压测若出现明显误判，再补等待图。

另外一条纪律：**桩函数一律返回 `kNotImplemented` 并打 WARN，不许静默返回"成功"**。骨架阶段宁可报错，也不能让人以为功能已经有了。

### 9. M0.5（同日）：存储层按大赛 RMDB 框架重排

**为什么改**：原来 `BufferPool` 一个类同时管文件、页、淘汰，和大赛 `src/storage` 的四件套对不上，答辩时没法顺着模块图讲；而且一个全局页号让 9 张表复用同一套页号，`orders` 和 `drivers` 的 page 0 会在页表里冲突。既然要"以大作业备赛"，先把骨架摆成赛题的样子。

**改成了什么**：
- 拆出 `DiskManager`（对应 `disk_manager`）：目录/文件开关、页读写、页号自增分配、WAL 日志接口；
- `Page` 改成固定数组 `char data_[kPageSize]`（同 rmdb），前 4 字节预留 page LSN，页头从第 4 字节开始（对齐 `OFFSET_PAGE_HDR = 4`）；
- `BufferPoolManager` 照 rmdb 的字段摆：`pool_size_ / pages_ / page_table_ / free_list_ / disk_manager_ / replacer_ / latch_`，方法 `FindVictimPage / UpdatePage / FetchPage / UnpinPage / FlushPage / NewPage / DeletePage / FlushAll`；
- 新增 `Replacer` + `LRUReplacer`（对应 `src/replacer`），接口原样 `Pin / Unpin / Victim / Size`；
- 缓冲池的键改成 `PageKey{fd, page_no}`：每个文件独立页号，9 张表不再抢同一个页号；
- 未实现处全部改成 rmdb 风格的 `TODO(题1-1)` / `TODO(题1-2)` 编号注释 + 显式失败返回，不再只有一句"待实现"。

**三个判断（都写进了 `docs/rmdb对齐说明.md`，答辩可直接引用）**：
1. **不把 fd 塞进 RID**。rmdb 的 `PageId` 带 fd，但我们的 RID 要落盘（索引叶子、事件关联），fd 是进程内句柄、重启就变，写进磁盘必炸。所以 RID 只存 (页号,槽号)，fd 由 `HeapFile` 持有，`PageKey` 只在缓冲池内部用。
2. **页大小仍 8KB**。记录 216B，4KB 只放 18 行、8KB 放 37 行；接口不依赖具体值，真要按 4KB 评测改 `kPageSize` 一个常量，但容量结论与热身 A 的数字要重算。
3. **错误用 Status 不用 throw**。与协议错误码、算子返回值同一条路径；代价是必须显式查返回值，所以桩函数一律返回失败，禁止静默成功。

**顺手发现上游一个小 bug**：rmdb 的 `BufferPoolManager` 构造函数用 `REPLACER_TYPE.compare("LRU")` 判断，`compare` 返回 0 才是相等，条件写反了——实际永远建 `LRUReplacer`。我们不复制这个坑，直接固定 LRU 并注释"CLOCK 属 W2 加分项"。

**验证**：5 个 target 全部编译通过（只剩"桩成员未使用"的预期告警），`m0_selftest` 34/34 PASS，`warmup_a/b/c` 全 PASS，`db_server --stdio` 的 PING/HELLO/QUIT 行为不变（`data/` 目录由 `DiskManager` 自动创建）。
